# Product API

A small FastAPI-based product management service built with SQLAlchemy, PostgreSQL, and pytest. The API exposes CRUD operations for products and includes API key validation for protected routes.

## Project overview

This project is a backend service for managing products. It supports:

- Creating a product
- Reading all products or a single product by ID
- Updating a product
- Deleting a product
- Securing endpoints with an API key
- Running tests with coverage reporting
- Running in Docker with PostgreSQL

---

## Project structure and file explanations

### app/

#### app/main.py

Main application entry point. It creates the FastAPI app, initializes database tables, and includes the products router.

#### app/database.py

Configures the database connection and the SQLAlchemy session. This file reads `DATABASE_URL` from environment variables and provides `get_db()` for dependency injection.

#### app/models.py

Defines the database model for the `Product` table. It includes fields like id, name, description, price, and quantity.

#### app/schemas.py

Contains Pydantic validation models for request and response payloads. This ensures proper validation for product create and update operations.

#### app/crud.py

Holds all database logic for CRUD operations. It contains functions for reading, creating, updating, and deleting products.

#### app/security.py

Handles API key validation. It reads `API_KEY` from the environment and blocks unauthorized requests via request headers.

#### app/routers/products.py

Defines the REST endpoints for product operations. It includes routes for create, read, update, and delete, all protected by API key dependency.

### tests/

#### tests/conftest.py

Provides shared pytest fixtures for the test database and dependency overrides. It creates a fresh in-memory/test database setup for each test.

#### tests/test_crud.py

Verifies the CRUD logic directly at the database layer.

#### tests/test_products_api.py

Tests the actual FastAPI endpoints and HTTP responses.

#### tests/test_security.py

Verifies that protected routes reject missing or invalid API keys.

### Root files

#### pyproject.toml

Project configuration for Python and dependencies. It defines the package metadata and required libraries, including FastAPI, SQLAlchemy, pytest, pytest-cov, and uvicorn.

#### requirements.txt

Simplified dependency list for standard pip-based installation.

#### uv.lock

Lock file generated by uv to ensure reproducible dependencies.

#### Dockerfile

Builds the application container and starts the FastAPI server with uvicorn on port 8000.

#### docker-compose.yml

Starts the application and PostgreSQL database together in Docker. It wire up the service container and database container.

#### .env.local

Development environment settings for running the app locally on your machine.

#### .env.docker

Docker environment settings used by the API container to connect to the database service named `db`.

#### .env.test

Test environment values used while running pytest in a test configuration.

#### .github/workflows/ci.yml

Defines the GitHub Actions CI pipeline that runs tests on code changes.

#### .github/workflows/cd.yml

Defines the GitHub Actions CD pipeline that builds and pushes the Docker image to GitHub Container Registry.

## Local setup with uv

This project uses `uv` as the package manager and runner.

### 1. Install uv

If uv is not installed:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### 2. Create environment and install dependencies

```bash
uv sync
```

### 3. Prepare local environment file

The app expects a `.env` file in the project root. Copy the local config into place:

```bash
cp .env.local .env
```

### 4. Run the API locally

```bash
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Then open:

```text
http://localhost:8000/docs
```

### 5. API header requirement

Requests to protected routes require:

```http
x-api-key: my-secret-api-key
```

This matches the value in `.env.local`.

## Dockerfile explanation

The Dockerfile is responsible for building the API container.

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

### What it does

- Uses a slim Python 3.12 base image
- Sets working directory to `/app`
- Installs Python dependencies from `requirements.txt`
- Copies the project source into the container
- Exposes port 8000
- Starts the FastAPI app with uvicorn

---

## docker-compose.yml explanation

The compose file defines two main services:

### `db` service

- Uses PostgreSQL 17
- Creates a database named `products_db`
- Exposes port `5432` for local database access
- Stores data in a named Docker volume called `postgres_data`

### `api` service

- Builds the app from the current Dockerfile
- Depends on the `db` service
- Uses `.env.docker` for environment settings
- Exposes the app on port `8000`

This setup makes local Docker development easy because the API and database start together.

## CI pipeline (Continuous Integration)

The CI workflow is defined in `.github/workflows/ci.yml`.

### Step by step

1. Trigger on push to `main` or `develop` and on pull requests to those branches.
2. Start a GitHub-hosted Ubuntu runner.
3. Start a PostgreSQL 17 service container.
4. Set environment variables:
   - `DATABASE_URL`
   - `API_KEY`
5. Check out the repository.
6. Install `uv`.
7. Set up the Python version from `.python-version`.
8. Verify the database is ready using `pg_isready`.
9. Run `uv sync` to install dependencies.
10. Execute tests with coverage using:

```bash
uv run pytest --cov=app --cov-report=term-missing
```

### Goal of CI

CI ensures that every code change is validated before merging. It helps catch:

- failing tests
- broken API behavior
- security regressions
- database setup issues

## CD pipeline (Continuous Delivery / Deployment)

The CD workflow is defined in `.github/workflows/cd.yml`.

### Step by step

1. Trigger on push to `main`.
2. Check out the repository.
3. Set up Docker Buildx.
4. Log in to GitHub Container Registry (GHCR).
5. Extract image metadata.
6. Build the Docker image.
7. Push the image to GHCR with tags like:
   - `latest`
   - commit SHA

This means every successful merge to `main` creates a fresh container image that can be pulled and deployed in a hosting environment.

### CD flow summary

```text
Code pushed to main
   -> GitHub Actions starts CD
   -> Docker build runs
   -> Image pushed to GHCR
   -> Deploy environment can pull the new image
```

## API endpoint cheat sheet

All product endpoints require this header:

```http
x-api-key: my-secret-api-key
```

### 1. Create product

```bash
curl -X POST http://localhost:8000/products \
  -H "Content-Type: application/json" \
  -H "x-api-key: my-secret-api-key" \
  -d '{
    "name": "MacBook Pro",
    "description": "Apple laptop",
    "price": 2499.99,
    "quantity": 5
  }'
```

### 2. Get all products

```bash
curl http://localhost:8000/products \
  -H "x-api-key: my-secret-api-key"
```

### 3. Get product by ID

```bash
curl http://localhost:8000/products/1 \
  -H "x-api-key: my-secret-api-key"
```

### 4. Update product

```bash
curl -X PUT http://localhost:8000/products/1 \
  -H "Content-Type: application/json" \
  -H "x-api-key: my-secret-api-key" \
  -d '{
    "name": "MacBook Air",
    "description": "Updated laptop",
    "price": 1799.99,
    "quantity": 4
  }'
```

### 5. Delete product

```bash
curl -X DELETE http://localhost:8000/products/1 \
  -H "x-api-key: my-secret-api-key"
```

## Approval and Slack curl reference

### Create approval

```bash
curl --location 'http://127.0.0.1:8000/approvals' \
  --header 'Content-Type: application/json' \
  --header 'x-api-key: my-secret-api-key' \
  --data '{
    "request_type": "CREATE_PRODUCT",
    "requested_by": "alice",
    "payload": {
      "name": "MacBook Pro",
      "description": "Apple laptop",
      "price": 2499.99,
      "quantity": 3
    }
  }'
```

### Get all pending approvals

```bash
curl --location 'http://127.0.0.1:8000/approvals' \
  --header 'x-api-key: my-secret-api-key'
```

### Get a single approval by ID

```bash
curl --location 'http://127.0.0.1:8000/approvals/APPROVAL_ID' \
  --header 'x-api-key: my-secret-api-key'
```

### Approve an approval request

```bash
curl --location 'http://127.0.0.1:8000/approvals/APPROVAL_ID/approve' \
  --header 'Content-Type: application/json' \
  --header 'x-api-key: my-secret-api-key' \
  --data '{
    "comments": "Approved by reviewer"
  }'
```

### Reject an approval request

```bash
curl --location 'http://127.0.0.1:8000/approvals/APPROVAL_ID/reject' \
  --header 'Content-Type: application/json' \
  --header 'x-api-key: my-secret-api-key' \
  --data '{
    "comments": "Rejected by reviewer"
  }'
```

### Slack actions webhook

```bash
curl --location 'http://127.0.0.1:8000/slack/actions' \
  --form 'payload=hello-from-slack'
```
